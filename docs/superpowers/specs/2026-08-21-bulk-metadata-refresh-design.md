# Массовое обновление метаданных фильмотеки

## Цель

Одноразово обновить фильмы, сериалы и мультфильмы данными Кинопоиска, чтобы ранее созданные записи получили сезоны, серии, рейтинги, актёров, роли, автоматические трейлеры и остальные возможности текущего pipeline импорта.

Обновление должно быть безопасным: неверные и неоднозначные совпадения не применяются, пользовательские данные не перезаписываются, а предварительный запуск не меняет базу.

## Формат запуска

Решение реализуется отдельной CLI-утилитой.

- Без `--apply` утилита работает в режиме dry-run и только формирует отчёт.
- С `--apply` подтверждённые записи сохраняются в базе.
- `--limit` позволяет проверить ограниченную выборку.
- `--movie-id` позволяет повторить обработку одной записи.
- Между фильмами используется настраиваемая задержка, чтобы не превышать лимиты API.

Регулярный cron, кнопка в административном интерфейсе и запуск при старте приложения в эту задачу не входят.

## Поиск и сопоставление

1. Для записи с сохранённым числовым ID провайдера Кинопоиска подробные данные загружаются напрямую.
2. Для записи без ID Кинопоиска или с источником Wikidata выполняется поиск по текущему названию.
3. Кандидат принимается автоматически только при одновременном совпадении:
   - типа: фильм, сериал или мультфильм;
   - года выпуска;
   - нормализованного текущего названия с русским или оригинальным названием кандидата.
4. Одинаковый ID, найденный через два API Кинопоиска, считается одним кандидатом.
5. Если точных кандидатов нет или осталось несколько разных ID, запись пропускается как `not-found` или `ambiguous`.

Для подробной загрузки используется текущий порядок провайдеров приложения: Kinopoisk.dev как основной источник и Kinopoisk Unofficial как fallback и источник недостающих данных.

## Обновляемые данные

Из выбранной карточки Кинопоиска обновляются:

- название, год, страна и описание;
- режиссёр, жанры, актёры и длительность;
- количество сезонов и полная структура сезонов и серий;
- внешние рейтинги;
- нормализованные карточки актёров и роли;
- автоматические трейлеры и тизеры;
- провайдер, внешний ID и дата успешного обновления.

Постер Кинопоиска заменяет внешний постер, но не заменяет загруженный пользователем файл в `/uploads/posters/...` или локальный seed-постер.

## Сохраняемые данные

Массовый импорт не меняет:

- ручные ссылки на трейлеры;
- ссылки «где смотреть»;
- загруженные пользователем постеры;
- пользовательские оценки и рецензии;
- списки просмотра;
- автора и даты создания записи;
- подписки, уведомления и другую пользовательскую активность.

Уведомления о массовом обновлении не создаются.

## Запись и отказоустойчивость

Каждый фильм обновляется отдельной транзакцией. Ошибка одной записи не останавливает весь прогон.

Перед записью проверяется итоговый `dedupeKey`. Если обновлённые название, год и тип конфликтуют с другой записью, фильм пропускается как `duplicate-conflict`; автоматическое слияние в этой операции не выполняется.

Пустой или частично недоступный ответ провайдера не должен удалять уже сохранённые подробные сезоны, актёров, рейтинги или видео. Для rich metadata используются существующие правила сохранения непустого provider snapshot.

## Отчёт

И dry-run, и apply выводят итоговые счётчики:

- `matched-by-id`;
- `matched-by-search`;
- `updated`;
- `not-found`;
- `ambiguous`;
- `duplicate-conflict`;
- `failed`.

Для пропущенных и ошибочных записей выводятся ID, название, год и причина. Отчёт не содержит токены и другие секреты.

## Проверка и производственный запуск

1. Покрыть тестами нормализацию названий, выбор точного кандидата, неоднозначность, сохранение ручных полей и защиту загруженного постера.
2. Выполнить typecheck, тесты и production build.
3. Закоммитить, отправить изменения и задеплоить приложение.
4. Запустить полный dry-run в production-контейнере с настроенными API-токенами.
5. Проверить отчёт на ложные совпадения.
6. Создать резервную копию PostgreSQL.
7. Выполнить запуск с `--apply`.
8. Проверить итоговые количества записей с источником Кинопоиска, сезонами, сериями, актёрами, рейтингами и видео.
